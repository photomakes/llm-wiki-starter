# Устройство хранилищ памяти и правил

Начните с задачи, контекст которой приходится восстанавливать. Положите каждую нужную запись туда, где её будут искать в следующей сессии.

| Материал | Основное место |
|---|---|
| Постоянное правило и границы действий | Проектный файл правил |
| Назначение проекта и карта документов | Паспорт проекта |
| Статус, следующий шаг и ожидание | Один реестр открытых задач |
| Принятое решение и причина | Проектный документ по теме |
| Знание для повторного использования | [Вика](../wiki/index.md) |
| Повторяемый способ работы | Методика в `share/` |

## Как читать и обновлять

Держите входной файл правил коротким. Он задаёт действия и даёт адреса. Из паспорта должно быть понятно, какие документы открыть. В большом проекте объедините связанные записи в локальной `__wiki/` и добавьте индекс.

При продолжении задачи сначала используйте доступный контекст, затем откройте реестр и относящиеся к задаче решения. Из реестра должны быть понятны результат, состояние, следующий шаг и условие возобновления. Фиксируйте предложение отдельно от принятого решения.

В конце работы обновите только сведения, которые изменились и понадобятся дальше. Закрытую задачу уберите из реестра, полезный результат сохраните по теме. Для старых версий используйте Git. Отдельную историю ведите, когда она помогает понять решение или содержит уникальные сведения.

## Как проверить

- Пройдите путь от входных правил до следующего действия по реальной задаче. Проверьте его в новом чате.
- Проверьте ссылки и найдите дубли статуса. После переноса оставьте одну рабочую запись и обновите указатели.
- Храните документы в Git. Для важных данных держите отдельную резервную копию и проверяйте восстановление. Секреты храните в предусмотренном для них хранилище.

В [демо-проекте](../projects/demo-project/README.md) показан полный маршрут от паспорта до задачи и решения.
